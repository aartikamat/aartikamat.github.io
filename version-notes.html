Version notes

I publish my data and papers openly, in numbered versions, so that anyone can check the results. In September 2026 I audited my own data pipelines. Where more data or the audit changed an estimate, I released a revised version; where a finding could no longer be supported, I withdrew it. The notes below record each change. Every earlier version stays available at its permanent identifier.

Post-Rejection Follow-up Sampling: Measuring Outcomes of Rejected Decisions in Algorithmic DEX Trading

Revised description

Correction in preparation: in the deployed data, the tracker sampled each tracked token at a fixed 10-minute cadence and kept one record per token, so the follow-up schedule and horizon described in the posted versions were not realised. A corrected version is in preparation.

Outcome-Classified Precision Auditing of Filter Rules in Algorithmic DEX Trading: Evidence from 2,400 Rejection Events

Revised analysis

Superseded: the posted versions (arXiv, SSRN and Zenodo) are superseded. Their wider headline ratio counted a token's quick disappearance from the price feed as a save; that outcome tier is withdrawn, because in these data follow-up usually ended at the token's next rejection rather than at token death. A rebuilt analysis, which compares the filters' saves and misses with what a fair game (prices with no predictable drift) would produce and replicates the comparison on later data, is in preparation.

RED-2400: A Public Benchmark of Algorithmically-Rejected Trading Events with Outcome Labels

Documentation updated; data unchanged

Correction: the preprint's comparison of tokens that left the price feed soon after rejection with other rejected tokens (Section V) is withdrawn. In these data, follow-up for a rejection event usually ends at the token's next rejection, not at token death, and the lifecycle tracker's "gone" state is not a verified token death. The Zenodo dataset record (version 4.0, September 2026) carries the corrected documentation; the data files are unchanged. A corrected version of the paper is in preparation.

Auditing Collector-Generated Graduation Labels on Pump.fun: Measurement Error and Temporal Non-Generalization

Estimates replaced in a later version

Correction notice (28 September 2026, dataset v1.6): the validation failure mainly reflects a calendar-spline term in the frozen model, not evidence that the market or the feature–label relationship changed; the analysis protocol, frozen after earlier analyses of the same data, is a pre-specified re-analysis protocol rather than a pre-registration; and the last day of the validation cohort is outcome-selected. Corrected versions of the paper are in preparation.

Correction (September 2026): the current arXiv version (v4) retracts the survival-analysis estimates of the earlier versions, including the pooled 0.198 percent graduation rate, the "3.18x decline" built on it, the Telegram "lift" figures and the wallet-intent narrative, because each treated the collector's label as the platform's graduation event. The earlier arXiv versions (v1 to v3) and the SSRN posting still show those claims and should not be relied upon.
